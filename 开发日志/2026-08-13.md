## 备注 / 问题
- 系统 python3 为 3.9.6，代码需兼容 3.9（如联合类型注解需 `from __future__ import annotations`）
- git 身份为本仓库本地占位（lindanlei@localhost），如以后要推送到远程需自行修改
- urllib3 在 macOS 上提示 LibreSSL 警告，无害可忽略
- 新浪日线列名与东财不同（date/close/amount），amount 为成交额、turnover 为换手率，勿混用；停牌日 volume=0 需剔除
- 踩坑记录：stock_daily 由新浪日线（close/turnover）与东财 datacenter（pe/pb）两源分写，缓存新鲜度必须按列判断（get_daily_last_date(code, col)），否则一源更新会"遮蔽"另一源
- 数据时点教训：① 新浪日线（stock_zh_a_daily）当日 K 线收盘后约 17:00~18:00 才发布，16:30 运行时技术分用的是昨日收盘价（2026-08-13 芭田股份由此误判 20/20，实际当日跌 2.9% 技术分应为 0）；② fetch_snapshot TTL=当天，收盘后同日需 force=True 才能刷新最终价。定时任务定在 18:30 + force 刷新快照
- Jinja2 模板注意：字典 key 为 "items" 时 `group.items` 会解析成 dict 方法而非键，必须用 `group['items']`
- 幂等重跑要点：冷却期查询必须排除当日已有推荐（get_recent_recommended_codes 的 exclude_date 参数），否则"先删后插"的覆盖式重跑每次都把上一轮当日推荐当冷却对象，选出的名单会一轮比一轮差
