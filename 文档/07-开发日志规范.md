# 07-开发日志规范

> 版本：v1.0 ｜ 2026-08-13 ｜ 状态：已定稿
> 定义开发日志的存放位置、格式和更新规则。日志由 Claude 自动维护，用户无需手动记录。

## 1. 位置与命名

- 目录：`开发日志/`
- 每天一个文件，命名：`YYYY-MM-DD.md`（如 `2026-08-13.md`）
- 一天只写一个文件，当天工作全部追加到当天文件

## 2. 文件模板

```markdown
# 开发日志 2026-08-13

## 今日完成
- [x] 完成事项描述（做了什么事，结果如何，尽量具体）

## 待办事项
- [ ] 未完成事项（继承自昨天 + 今天新增）
  - 说明：需要什么前提 / 卡在哪里

## 明日计划
- [ ] 计划明天做的事

## 备注 / 问题
（遇到的问题、踩的坑、对后续有参考价值的信息；没有可写"无"）
```

约定：
- 完成的事项用 `- [x]`，未完成用 `- [ ]`
- 每条一行，写"做了什么 + 结果"，不写流水账
- 待办要具体到能直接执行（如"实现 data_fetcher 的全市场快照函数"），不写"继续开发"

## 3. 更新规则（Claude 自动执行）

| 时机 | 动作 |
|---|---|
| **会话开始** | ① 运行 `python scripts/devlog.py`（创建今日文件、自动继承最近日志的未完成待办）② 读取最新日志，了解进度后开始工作 |
| **完成一个任务/阶段** | 立即把完成事项写入"今日完成"并勾选；待办有变化时同步更新 |
| **会话结束 / 用户结束工作前** | 更新"今日完成"与"待办事项"，写下"明日计划"；没有新完成事项也要确认日志与当天实际工作一致 |
| 进入新一天 | 同上，devlog.py 自动把昨天未完成的"待办/明日计划"继承为今天的待办 |

## 4. 待办继承机制（devlog.py）

- 脚本扫描 `开发日志/` 下**日期最近**的文件，提取"待办事项"和"明日计划"中所有 `- [ ]` 未勾选项
- 把它们复制为新一天日志的"待办事项"初始内容
- 若最近文件已不存在未完成待办，新日志的待办区写"（无继承待办）"

## 5. 日志用途

- 给用户看：今天做了什么、接下来要做什么（一句话能说清进度）
- 给 Claude 看：断点续接——隔天、隔周继续开发时快速恢复上下文
- 写日志本身也算工作的一部分，不要省略
