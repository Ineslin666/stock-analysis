# 05-开发计划与执行步骤

> 版本：v1.0 ｜ 2026-08-13
> 本文档是项目的执行路线图。**每次会话开始先读本文件确认当前阶段。**

## 1. 执行规则（强制）

1. **小步推进**：一次只做一个阶段（甚至阶段内的一个步骤），做完验收、提交 git，再进入下一步
2. **验收准入**：上一阶段未通过验收标准，禁止开始下一阶段
3. **规范先行**：写代码前先读对应规范文档（选股→04，界面→03，数据→06）
4. **阶段收尾三件事**：更新开发日志 → 更新本文件阶段状态 → git 提交

## 4. 阶段 1 执行步骤（数据层）

1. 1.1 接口验证：逐个实测 akshare 接口（全市场快照、单股历史行情、财务指标、历史 PE/PB、股息率、股票列表、交易日历），记录接口名/参数/返回列到 `docs_notes/`（临时笔记）并确认哪些可用
2. 1.2 实现 data_fetcher.py：
   - 全市场快照（含 PE/PB/市值/行业），缓存到 SQLite
   - 单只股票历史日线（收盘价/成交额），带重试与限流
   - 单只股票财务指标（ROE/营收/净利/负债率/现金流）
   - 单只股票历史 PE/PB 序列（分位计算用）
   - 股息率、股票列表（含上市日期）、交易日历
3. 1.3 缓存策略：同一天内同一数据只拉一次；日线增量更新
4. 1.4 验收：任选 3 只股票（如贵州茅台 600519、宁德时代 300750、招商银行 600036）全量拉取数据，检查字段完整性与数值合理性（与行情软件比对）

## 5. 阶段 2 执行步骤（选股引擎）

1. 2.1 按 04 规范实现逐关筛选函数（基础过滤→质量关→估值关），每关输出通过数量便于调试
2. 2.2 实现打分模型（质量 40 + 估值 40 + 技术 20）
3. 2.3 实现行业分散与 60 天冷却期（读推荐记录表）
4. 2.4 生成筛选理由文本
5. 2.5 验收：命令行运行，输出 3 只股票；人工抽查其中 1 只核对每个指标与阈值判断正确

## 6. 阶段 3 执行步骤（结论引擎）

1. 3.1 设计结论规则（写入 04 规范 §9）：
   - PE 分位 < 30% 且技术分 ≥ 14 → 值得买入
   - PE 分位 30%~50% 或技术分 8~13 → 可以买入，建议分批
   - 其他 → 暂不建议买入
2. 3.2 参考价位：MA20 ~ MA60 区间；或 PE 分位 30% 对应的历史价格
3. 3.3 验收：对阶段 2 输出的 3 只生成结论，逻辑可复算
