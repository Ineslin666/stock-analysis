# 05-开发计划与执行步骤

> 版本：v1.0 ｜ 2026-08-13
> 本文档是项目的执行路线图。**每次会话开始先读本文件确认当前阶段。**

## 1. 执行规则（强制）

1. **小步推进**：一次只做一个阶段（甚至阶段内的一个步骤），做完验收、提交 git，再进入下一步
2. **验收准入**：上一阶段未通过验收标准，禁止开始下一阶段
3. **规范先行**：写代码前先读对应规范文档（选股→04，界面→03，数据→06）
4. **阶段收尾三件事**：更新开发日志 → 更新本文件阶段状态 → git 提交

## 4. 阶段 1 实测结论（数据层，已完成 2026-08-13）

1. 1.1 接口验证：已完成，实测记录见 `docs_notes/01-接口实测记录.md`。关键结论：
   - **东财 push2 系接口在本机网络被服务端断连**（全市场快照/行业成分股/东财日线/东财个股信息），curl 直测亦失败 → 数据源以**新浪体系为主**（全市场快照、日线、财务指标、分红、资产负债表）
   - 历史 PE/PB 日序列用东财 datacenter 的 `stock_value_em`（可用）
   - 新浪行业板块只覆盖约 3000 只，其余约 3200 只用巨潮 `stock_profile_cninfo` 的证监会 2012 大类补源（缓存在库）
   - 派息数据单位是"每 10 股"，且需过滤"预案"只算"实施"
2. 1.2~1.3 已实现：db.py（列级合并写入、按源分写、TTL 缓存）+ data_fetcher.py（快照/列表/日历/财务/估值历史/日线/股息率/商誉 + 重试限流）+ scripts/check_data.py 验收脚本
3. 1.4 验收：以 600519/300750/600036 全量拉取并比对合理性区间（scripts/check_data.py）
4. 阶段 1 遗留事项（转入阶段 2 处理）：全市场财务指标的首次全量拉取（约 5200 只 × 1.2s ≈ 2 小时，作为阶段 2 选股的首步执行）；行业补源对全市场执行一次（约 40 分钟）

## 6. 阶段 3 执行步骤（结论引擎）

1. 3.1 设计结论规则（写入 04 规范 §9）：
   - PE 分位 < 30% 且技术分 ≥ 14 → 值得买入
   - PE 分位 30%~50% 或技术分 8~13 → 可以买入，建议分批

3. 3.3 验收：对阶段 2 输出的 3 只生成结论，逻辑可复算
